The top-level file: every hardware and board, and every oscilloscope.

---

The main Excel file is the one placed in the data root folder, named `Classic-Repair-Toolbox.v2.0.0.xlsx` (or `Classic-Repair-Toolbox.xlsx` for the oldest versions of CRT). It lists the hardware and boards in CRT's drop-down lists, and it has the configuration for all supported oscilloscopes.

The Excel file, alongside the board Excel files, is versioned: the version number in its name is the first CRT version it works with. CRT uses the newest `Classic-Repair-Toolbox.v<version>.xlsx` that is not newer than CRT itself, and the unversioned file only when there is none.

**You do not edit this file to add a board.** A new board is made with **Add a new system** - see [Add a new board with KiCad data](Add-new-board-with-KiCad-data). When it is published, the maintainer who accepts it chooses its names and its place in the lists, and the server adds its row here.

The Excel file has only two worksheets, so it is pretty simple compared to the board files.

Each worksheet opens with a few lines starting with `#`. On **Hardware & Board** the third is the revision date, for example `# Revision date: 2026-October-4`. Whenever the server writes the file - a new system added to the lists, a system removed from them, or the systems put in a new order by the administrator (Maintainer tab, **Account** > **Order of systems**) - it sets that date to the day of the change. The **Oscilloscope** worksheet's `# Revision date:` line is updated the same way when it has one; a missing line is never added.

The headers stay in view while you scroll: the **Hardware & Board** worksheet is frozen under its header row, and the **Oscilloscope** worksheet under its header row and after its second column, so the brand and model stay visible however far to the right you scroll.


## Worksheet: Hardware & Board

These are the columns and how to understand them. All four headers must be there, or no boards are listed at all.

The rows are in the order CRT shows them in its drop-down lists.

### Column: Hardware name in drop-down

Exact same name as shown in the `Hardware` drop-down list in CRT.\
The exact same hardware name can be represented on multiple rows, if it has different boards. A blank cell takes the hardware name from the row above.\
Keep the name short, so it can fit in the drop-down.

### Column: Board name in drop-down

Exact same name as shown in the `Board` drop-down list in CRT.\
The same board name must _not_ be represented more than once per hardware.\
Keep the name short, so it can fit in the drop-down.\
This is typically the model number or for a Commodore system it is the "assy" (yeah, weird naming).

### Column: Excel data file

Path and filename to the specific hardware/board Excel data file.\
Use **relative** path from the `Data` folder, with `/` between the folders - for example `Commodore/C64/250407/Data C64 250407 v2.0.0.xlsx`.

### Column: Hardware notes in "Overview" tab

A small note describing characteristics of the hardware - maybe special recognition points.\
For a new system it is what was typed in the **Notes** box of "Add a new system", and the maintainer who places the system can change it.\
Currently this data is not displayed anywhere, but it should be one day.

## Worksheet: Oscilloscope

One row per scope brand/series. Copy the row for a scope closest to yours and adjust it - **you will
need your scope's programming manual**, because SCPI commands vary between vendors and even between
models from the same vendor.

The `Brand`, `Series or model` and `Port` headers must be there. A blank `Brand` takes the brand from
the row above, and a row with no `Series or model` is skipped.

`{0}` in a command is where CRT substitutes the actual value.

| Column | What goes in it |
| --- | --- |
| `Brand` | The vendor name |
| `Series or model` | Ideally a whole series/family, but a single model works too |
| `Port` | Default network port. Changeable in the "Oscilloscope" tab. |
| `Debounce-Time` | How long to wait between commands, with its unit, e.g. `100ms`. Used for image handling and keyboard repeat. |
| `Identify` | Returns vendor, model, serial and firmware |
| `DrainErrorQueue` | Returns the next error from the scope's error queue |
| `Operation-Complete` | Asks whether the scope is ready for the next command |
| `Clear-Statistics` | Clears statistics/status values |
| `QueryActiveTrigger` | Returns the trigger state: `Running`, `Waiting`, `triggered` |
| `Stop` | Freezes acquisition now |
| `Single` | Stops at the next trigger point |
| `Run` | Resumes acquisition |
| `QueryTriggerMode` | Returns the trigger mode, e.g. `Edge` |
| `QueryTriggerLevel` | Returns the trigger level in volts |
| `SetTriggerLevel` | Sets the trigger level - `{0}` is the level in volts |
| `QueryTimeDiv` / `SetTimeDiv` | Time per division, e.g. `1uS` = 1 microsecond per horizontal division |
| `QueryVoltsDiv` / `SetVoltsDiv` | Volts per division, e.g. `1V` per vertical division |
| `DumpImage` | Fetches the current screen over the network. Differs a lot per vendor and model. |
| `TIME/DIV` | Every `T/DIV` value your scope offers, separated by commas, e.g. `1uS,2uS,5uS` |
| `VOLTS/DIV` | Every `V/DIV` value your scope offers, separated by commas, e.g. `500mV,1V,2V` |

> [!WARNING]
> `TIME/DIV` and `VOLTS/DIV` must both be filled in, not just the command columns. The numpad
> stepping keys look up the current value in those lists, and do nothing if it is not there.
